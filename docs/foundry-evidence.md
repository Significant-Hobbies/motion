# Foundry Evidence

Privacy-safe build, simulator, signing, device, and deployment evidence for the
Foundry (`saas-maker`). Generated by `scripts/foundry-evidence.sh` and uploaded
as a CI artifact on every push to `main` and weekly (Mondays 06:00 UTC).

## Why

Motion is an undeployed Apple-platform body-motion POC that processes camera
input on-device. The Foundry needs to know whether the project builds, whether
the Simulator compiles, and what blocks signing/device/deployment — without
receiving any camera frames, motion samples, speech samples, screenshots,
credentials, or device identifiers. This script produces aggregate, sanitized
state only.

## Run locally

```bash
./scripts/foundry-evidence.sh
# → writes foundry-evidence.json (gitignored)
```

The script runs `npm run typecheck` and `npm run build` (web), then attempts
the iOS Simulator build if Xcode + xcodegen are available. No camera, no
device, no network calls.

## State model

Motion distinguishes five states, per the spec:

| State | Values | Meaning |
| --- | --- | --- |
| `build.typecheck` | `pass\|fail\|skip` | `npm run typecheck` (server + web) |
| `build.web` | `pass\|fail\|skip` | `npm run build` (web game) |
| `simulator.state` | `pass\|fail\|blocked` | iOS Simulator compile (`CODE_SIGNING_ALLOWED=NO`) |
| `signing.state` | `blocked` | No signing team in CI; device signing needs human approval |
| `device.state` | `blocked` | No physical device in CI; camera + ReplayKit need a device |
| `deploy.state` | `intentionally_undeployed` | v1 POC; no production target approved |

**Blocked is not failure.** A blocked state means the check cannot run in the
current environment, not that the code is broken. `fail` means the check ran
and the code did not pass.

## Schema (`private-local-toolbox-automation/v1`)

| Field | Type | Privacy note |
| --- | --- | --- |
| `project` | `"motion"` | static |
| `generatedAt` | ISO timestamp | — |
| `privacy.contentExcluded` | `true` | guarantees no content fields |
| `privacy.excludedFields` | string[] | lists what is NOT included |
| `build.typecheck` | string | aggregate only |
| `build.web` | string | aggregate only |
| `simulator.state` | string | aggregate only |
| `simulator.note` | string\|null | blocker reason if blocked |
| `simulator.codeSigning` | `"not_required"` | static (Simulator build) |
| `signing.state` | `"blocked"` | static (CI has no signing team) |
| `signing.blocker` | string | human-readable blocker |
| `device.state` | `"blocked"` | static (CI has no physical device) |
| `device.blocker` | string | human-readable blocker |
| `deploy.state` | `"intentionally_undeployed"` | static |
| `deploy.note` | string | rationale |
| `telemetry` | `"none"\|"partykit_relay_only_v2_parked"` | static |
| `blockers` | string[] | external blockers |
| `pendingApproval` | string[] | actions requiring human approval |

## Privacy guarantees

The evidence script NEVER reads:

- Camera frames or Vision pose output
- Motion samples, speech samples, or game state
- Screenshots or screen recordings
- Device identifiers or signing credentials
- User identifiers

It only runs build commands and records their exit codes + the static
signing/device/deploy states.

## No hosted telemetry

Motion does not send any data to the Foundry or any backend. The
`server/` PartyKit relay is v2-parked and not deployed. The evidence artifact
is a static JSON file uploaded as a CI artifact with 30-day retention — no
hosted data plane is created.
